# Evo Talos SDLC Kit - Release Notes v0.12

**Release Date:** 2026-09-17

---

## Overview

v0.12 fixes a defect in `orchestrator-bash-guard`'s transient-cleanup carve-out that made the kit's own §9 Step 7f journal cleanup unexecutable for anyone who wrote the path in one of the spellings the kit's rules themselves use.

Upgrade is recommended for every project running the kit.

---

## Major Features & Changes

### 1. The cleanup carve-out accepts the path spellings the Orchestrator rules write

**What changed:**
- `isOrchestratorCleanupRemoval` is replaced by `classifyCleanupRemoval`, which expands `$CLAUDE_PROJECT_DIR`, `${CLAUDE_PROJECT_DIR}`, `$PWD`, `${PWD}` and a leading `~/` before resolving each operand, and refuses every other variable or command substitution.
- 21 new hook tests cover the accepted spellings, the refused ones, and the refusal messages.

**Why:**
The carve-out refused any operand containing `$`, a backtick or a leading `~`. `rules/orchestrator-operating-rules.md` §9 Step 7f mandates deleting the dispatch journal, and an Orchestrator writing that path as `$CLAUDE_PROJECT_DIR/.claude/dispatch-journal/<role>-<task-id>.json` — an entirely idiomatic spelling — fell through the carve-out to the general `rm` block. The documented step was unexecutable, and §9's "no escape hatch is needed" was true only for a form the prose never stated.

This is the ISSUE-179 rule applied to a second guard: **a guard must not hard-code a format an upstream artifact owns.** The path spelling belongs to the Orchestrator rules, not to the guard. The strict-descendant proof, not the spelling, is what makes the carve-out safe — and it is unchanged.

**Impact:**
- `$CLAUDE_PROJECT_DIR`-, `$PWD`- and `~`-rooted cleanup targets are accepted when they resolve strictly below `.worktrees/` or `.claude/dispatch-journal/`.
- Expansion is an allowlist. `$HOME/...`, `$SOME_DIR/...` and `` `cat /tmp/x` `` remain refused, so no operand can reach the descendant check unresolved.
- Cleanup-root removal, mixed targets, traversal escapes, symlinked components, `rmdir -p` and shell composition remain blocked.

### 2. A refused cleanup names its own disqualifier

**What changed:**
A removal that names a cleanup surface but does not qualify now gets a dedicated message stating the actual reason — `composition`, `unexpanded-variable`, `outside-cleanup-roots`, `rmdir-parents`, `no-targets` or `symlink-or-glob` — the accepted spellings, and the canonical Step 7f form.

**Why:**
The old path fell through to the generic block, which told the author *"rm without protective flags — sub-agent territory"*. That describes neither the cause nor a usable remedy: it sends an author hunting for a worktree when the real disqualifier was a dollar sign. **A guard's failure message must name the real cause** (ISSUE-179).

The message also states explicitly that `CLAUDE_ALLOW_ORCHESTRATOR_BASH` is not the remedy. The hook process reads that variable from the harness environment at start-up, so an inline `VAR=1` prefix on the command can never reach it — and manufacturing a bypass for a check working as designed is what the kit forbids.

### 3. Scope guard on the new message

A removal that names no cleanup surface is not an attempted carve-out use and keeps the original generic guidance, so ordinary mis-scoped work is still explained correctly. Tests pin both directions.

## Upgrade Notes

The v0.11 note still applies and is the reason this fix may appear not to land: the guard runs from **both** copies when a project registers its own. Every registered copy runs and any one exiting 2 blocks the call, so enforcement is the union of all copies' blocks — a carve-out is inert until every registered copy has it. Updating the plugin alone does not unblock a project whose vendored `.claude/hooks/` copy predates this release; re-run `sdlc-init` or refresh that copy.

A project that has both the plugin enabled and its own vendored registrations runs every guard twice. That is harmless while the copies agree and becomes strictest-wins the moment they diverge. Prefer one surface.
