# Evo Talos SDLC Kit - Release Notes v0.13

**Release Date:** 2026-09-17

---

## Overview

v0.13 fixes a read-buffer limit in the promotion gate that made a correctly promoted artifact read as missing, refusing a legitimate worktree teardown.

Upgrade is recommended for every project running the kit, and required for any project whose dispatches promote artifacts larger than 1 MiB.

---

## Major Features & Changes

### 1. `dispatch-promotion-state`'s git reader is sized for real artifacts

**What changed:**
- `git()` in `hooks/lib/dispatch-promotion-state.cjs` now passes `maxBuffer: 64 MiB`. It previously passed none, so it ran on Node's `execFileSync` default of **1 MiB**.

**Why:**
`unpromotedPaths()` reads each manifest entry with `git show HEAD:<path>`, streaming the whole artifact through that buffer. A promoted artifact routinely exceeds 1 MiB — a generated OpenAPI contract, a lockfile, a fixture. On overflow `execFileSync` throws, `git()` returned `null`, and `null` at that call site means *"not on HEAD"*. So an artifact that **had** been promoted was classified `missing`, the dispatch read as **partially promoted**, and `worktree-promotion-guard` refused the teardown.

**Impact and direction of the failure:**
The bug was **fail-closed** — it blocked teardown rather than allowing one over unpromoted work, so no dispatch output was ever at risk. What it cost was a blocked run and a **false explanation**: the guard named a file as `MISSING on HEAD` while that file sat in HEAD, sending an operator to look for a promotion failure that had not happened.

### 2. A buffer overflow no longer reports itself as an absent path

**What changed:**
`git()` distinguishes a buffer overflow (`ENOBUFS` / `ERR_CHILD_PROCESS_STDIO_MAXBUFFER`) from a git non-zero exit, and writes a stderr note naming the limit and stating that it is **not** evidence the path is absent from HEAD.

**Why:**
Both conditions landed in the same bare `catch` and both returned `null`, but they mean different things: a git failure is a fact about the repository, an overflow is a limit of the hook process. Callers read `null` as "absent". This is the ISSUE-179 rule again — **a guard's failure message must name the real cause** — and it is why the 1 MiB default went unnoticed: the symptom was indistinguishable from the thing the gate exists to detect.

`null` is still what is returned. Fail-closed is the correct direction for a promotion gate; only the silence was wrong.

### 3. Regression coverage

`hooks/tests/test-promotion-gate.sh` gains a `bigblob` scenario: a fully and correctly promoted dispatch carrying a 3 MB artifact. Two assertions — teardown is allowed, and `MISSING on HEAD` does not appear. Verified to fail (2/2) when `GIT_MAX_BUFFER` is set back to 1 MiB, so the test pins the defect rather than the fix.

## Upgrade Notes

The v0.11 and v0.12 notes still apply: the hooks run from **both** copies when a project registers its own, and enforcement is the union of every registered copy's blocks. Updating the plugin alone does not change a project whose vendored `.claude/hooks/` copy predates this release — re-run `sdlc-init` or refresh that copy.
