# Evo Talos SDLC Kit - Release Notes v0.14

**Release Date:** 2026-09-17

---

## Overview

v0.14 gives the executable half of a QA-Author case pack an owner. Two guards refused those paths, so a QA-Author dispatch could land its case pack and silently not land the specs that drive it.

Upgrade is required for any project whose QA-Author dispatches write `integration_test/by_{us,task}/` or `frontend/<app>/e2e/specs/by-{us,task}/`.

---

## Major Features & Changes

### 1. `role-ownership` knows the executable half of a case pack

**What changed:**
- Four rows added to `OWNERSHIP_MAP`, all `QA-Author`-owned: `integration_test/by_us/`, `integration_test/by_task/`, `frontend/<app>/e2e/specs/by-us/`, `frontend/<app>/e2e/specs/by-task/`.

**Why:**
A case pack has **two halves living in different trees** — the selectable case docs under `docs/test-cases/` (which had rows) and the executable specs that drive them (which had none). Those spec paths resolved to `null` ownership, so `orchestrator-write-guard` refused them as `unrecognized-path`. The pack landed; the spec did not. Hit on **T-248**, and earlier on **T-219 / T-220**, where 27 already-written specs were stranded.

**Scoping, and why it is narrow:**
The rows cover the two per-mode subdirectories only, not all of `integration_test/` or `e2e/`. `helpers/`, `fixtures/`, `pages/`, `goldens/` and `utils/` are shared across modes and app-bootstrap tests, owned by no role, and must keep forcing operator classification.

**The separator trap:** the Flutter tree is `by_us` / `by_task` (**underscore**) and the Playwright tree is `by-us` / `by-task` (**hyphen**). A row written with the wrong separator silently never matches, which is how a whole tree goes unowned with nothing failing. Both spellings are now pinned by tests in both directions.

### 2. `source-code-write-guard` defers to the ownership map

**What changed:**
- `isSourceCodePath()` returns `false` for any path the ownership map grants a kit role, consulted before the `isSrcDirPath / isE2ESpecPath / isCustomDirPath` decision.

**Why:**
The two guards disagreed about the same path. The map says QA-Author owns the pack spec trees; `isE2ESpecPath()` said a Playwright spec was source code, so a logically isolated doc-role write to the shared tree was blocked.

**The asymmetry this closes, because it is the trap:** `isE2ESpecPath` is an **exemption** in `layoutViolation()` (the worktree-relative check) but a **positive match** in `isSourceCodePath()`. The same spec was therefore not-source inside a worktree and source outside one. Consulting the map settles both consistently instead of maintaining a second hard-coded list that drifts from it.

**Fails closed:** if the map is unavailable the exemption does not fire and the block stands. The exemption cannot launder a non-pack path — `e2e/specs/smoke.spec.ts` and `lib/src/main.dart` are still blocked.

### 3. Regression coverage — the reason this sat unreleased

These two fixes were written on 2026-09-15 and lived only as uncommitted working-tree edits in two separate repos, hand-applied to each. **There was no test touching any of those paths**, so nothing forced the issue and the fix reached no consumer — the same "authored, never released" shape the v0.12 and v0.13 notes describe one layer down.

14 assertions added to `test-hooks.sh`: both guards, both trees, the allowed paths, the still-blocked shared directories, and both halves of the separator trap. Verified to fail 6/6 against the pre-fix hooks.

---

## Upgrade Notes

The v0.11–v0.13 notes still apply: hooks run from **both** copies when a project registers its own, and enforcement is the union of every registered copy's blocks. Re-run `sdlc-init` or refresh the vendored copy.

**If a project's vendored `.claude/hooks/` was hand-patched with these two fixes before this release, refreshing it from an older plugin version will overwrite them and reintroduce the T-248 failure.** Refresh to 0.14.0 or later.
