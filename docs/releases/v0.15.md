# Evo Talos SDLC Kit - Release Notes v0.15

**Release Date:** 2026-09-17

---

## Overview

v0.15 fixes a false positive in the promotion gate that blocked the teardown of dispatches whose content **was** promoted, and whose block survived into every later session.

Upgrade is required for any project whose Orchestrator edits a promoted path after closing a dispatch — which is every project, because triaging `docs/open-issues.md` after a closure does exactly that.

---

## Major Features & Changes

### 1. A promotion is an event, not a current state

**What changed:**
- `unpromotedPaths()` now receives `finalization.main_commit` and checks each manifest path at **that commit as well as HEAD**. A path whose worktree content matched main at either point is promoted.

**Why:**
The check compared the manifest against **HEAD only**, which asks the wrong question — *"does main look like the worktree right now?"* A promotion happened at `finalization.main_commit`, and main is **expected** to advance afterwards: the Orchestrator triages `docs/open-issues.md`, a later dispatch amends a contract, a doc is edited. Every one of those made a correctly promoted path read as `differing`, classified a finished dispatch `partially-promoted`, and refused its teardown.

**Why it was worse than a one-off nuisance:**
The block is **sticky**. An un-teardownable dispatch leaves its journal entry behind, so the false positive is re-raised in every later session and never ages out. `ISSUE-224` predicted this consequence before it was observed; `devops/T-259` is where it landed, with `docs/open-issues.md` reported as `DIFFERS from HEAD` because the Orchestrator had triaged `ISSUE-241` and resolved `ISSUE-239` *after* promotion. Main was ahead, not behind.

**The escape hatches were the wrong shape, and that is a feature:**
`CLAUDE_DISCARD_INTERRUPTED_DISPATCH` is for exit criteria that never ran; these ran and succeeded. `CLAUDE_ALLOW_UNPROMOTED_CLEANUP` destroys completed work; the work was demonstrably on main. Neither describes "the guard is wrong", and an operator should not have to pick the least-wrong override to get past a defect. **A guard must not be satisfiable only by a false assertion** — the ISSUE-179 rule, reached here from the operator's side.

**The gate is not weakened.**
Content that was never on main matches **neither** the promotion commit nor HEAD, and is still reported by path. `missing` now requires absence at both points. The dangerous case the gate exists for — a `finalized` marker over artifacts that were never copied — fails exactly as before.

### 2. Regression coverage

`test-promotion-gate.sh` gains a `postpromotion` scenario: a complete, correct promotion followed by a commit on main that edits one manifest path. Three assertions — teardown is allowed, `DIFFERS from HEAD` is not reported, and a genuinely unpromoted path is still blocked. Verified to fail 2/2 against the HEAD-only comparison.

---

## Upgrade Notes

A dispatch already stuck in this state needs no manual intervention beyond the upgrade: its journal entry and worktree are intact, so re-running the teardown after refreshing the kit re-classifies it as `promoted` and proceeds.

The v0.11–v0.14 notes still apply: hooks run from **both** copies when a project registers its own, and enforcement is the union of every registered copy's blocks. Refresh the vendored `.claude/hooks/` copy as well as the plugin — a fix present in only one copy is inert.
