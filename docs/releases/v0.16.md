# Evo Talos SDLC Kit - Release Notes v0.16

**Release Date:** 2026-09-17

---

## Overview

v0.16 completes the promotion-gate fix v0.15 started. v0.15 handled main advancing **after** the promotion commit; this handles the case where the promotion commit **itself** carries the Orchestrator's closure edits — which is every dispatch that files an issue.

---

## Major Features & Changes

### 1. A shared-doc is verified by promotion, not by equality

**What changed:**
- When a manifest path's content matches main at neither the promotion commit nor HEAD, and the ownership map classifies it `shared-doc`, the proof becomes: **did the promotion commit modify this path?**

**Why:**
`docs/open-issues.md` is append-only for all roles (CLAUDE.md §6) and the Orchestrator **must** edit it at closure, triaging the very issues the dispatch filed — in the promotion commit. So the promotion commit carries the agent's entry *and* the triage, and the worktree copy is byte-identical to main at **no commit, ever**.

v0.15 assumed main drifted *after* the promotion. On `devops/T-259` it had not: at `736a643f` the file already read `ISSUE-239: resolved` / `ISSUE-241: deferred` while the worktree copy read `deferred` / `open`. Checking the promotion commit as well as HEAD therefore changed nothing, and a complete promotion stayed unprovable and permanently blocked.

**Why this is safe, and how that is enforced rather than asserted:**
The fallback is **weaker** — "the commit wrote this path" cannot tell a correct ingestion from a truncated one — so it is **narrow**. It applies to `shared-doc` paths only, taken from the ownership map, never from a hard-coded filename. Every role-owned artifact keeps strict content equality.

Two tests pin the narrowing from the outside. A shared-doc the promotion commit never touched still blocks. And a **role-owned artifact written by the promotion commit with the wrong content** still blocks — the partially-promoted state the gate calls *"the dangerous one: every bookkeeping signal says success"*. Removing the `shared-doc` restriction makes that second test fail, which is what makes the restriction load-bearing rather than decorative.

### 2. The weaker check is stated, never silent

A dispatch that passes on the shared-doc fallback says so on stderr, naming each path and the commit that modified it. A gate that quietly relaxes itself stops meaning anything; the operator sees which paths took the weaker route and can disagree.

### 3. The block message no longer names the wrong comparison

`MISSING on HEAD` / `DIFFERS from HEAD` became `ABSENT at the promotion commit AND at HEAD` / `MATCHES NEITHER the promotion commit nor HEAD`. Since v0.15 the check reads two commits, and a message naming one of them misdescribes its own failure — the ISSUE-179 rule.

---

## Upgrade Notes

A dispatch stuck in this state needs no manual intervention: its journal entry and worktree are intact, so re-running the teardown after refreshing re-classifies it and proceeds. `devops/T-259` verified directly against the real repository — `partially-promoted` before, `promoted` after, with `docs/open-issues.md` reported under `sharedAdvanced`.

The v0.11–v0.15 notes still apply: hooks run from **both** copies when a project registers its own, and enforcement is the union of every registered copy's blocks. Refresh the vendored `.claude/hooks/` copy as well as the plugin.
