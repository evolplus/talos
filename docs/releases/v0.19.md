# Evo Talos SDLC Kit - Release Notes v0.19

**Release Date:** 2026-09-25

---

## Overview

v0.19 comes out of an audit of the consuming project's (4Run) open-issues log. Of 290 entries, every one that blamed kit tooling was reproduced against the shipped hooks. The kit defects that still reproduced are fixed here, **as defect classes rather than single instances**. Every fix has regression tests that were run against the 0.18.0 code first, to show they fail there.

Two patterns come up again and again:

1. **Silent skips.** A check quietly checked nothing (a label it could not parse, a worktree name it could not split, a second table it could not see), and it looked the same as a pass.
2. **Honest declarations punished.** The truthful form (`N/A`, `Design sub-status: n/a`, `Linked Surface: null`) was the one that got blocked, while leaving the line out passed. That teaches authors to stop declaring things.

## Fixes

### 1. Promotion gate: every dispatch stem is visible (ISSUE-200) — safety-critical

`worktree-promotion-guard` found its teardown target by parsing the worktree stem with `/^(role)-(LETTERS-DIGITS)$/`. Real stems add suffixes and batches (`devops-T-048-redeploy`, `qa-exec-T-049-T-051-T-052`), use lowercase ids (`be-dev-t-026-admin-academy`), or have no T-number (`ba-account-deletion-login-prompt`). That is **87 of the 254 real 4Run stems (34%)**. For each of these the parse returned null, the guard saw **no target**, and `git worktree remove` of an **unpromoted** dispatch exited 0. The Stop/SessionStart audit could not see them either.

- New `hooks/lib/kit-roles.cjs` is the kit's single list of role names. It splits a stem on the longest matching role prefix (aliases: `ui-ux`, `be`, `fe`). The journal's own `role` field is used as a hint when present. An unknown role falls back to the old split, then to a split at the first hyphen. **A stem is never dropped.** The invariant `${role}-${taskId} === stem` holds, so journal and worktree paths are rebuilt exactly.
- 13 new promotion-gate assertions. 9 of them fail on 0.18.0.

### 2. Validator roles can write their own signal (ISSUE-209)

`plan-update-validator` rejected `agent: architecture-validator`, `extraction-validator` and both SRS validators as "invalid agent". It also rejected `verdict` / `report_path` / `next_action` as "unknown field", even though each role's template tells it to write those keys. `VALID_AGENTS` is now derived from `kit-roles.cjs`. The three fields are accepted as optional, and `verdict` must be `qualified | unqualified`. The `srs-source-validator` template wrote `agent: srs-validator`. It is corrected, and the legacy name is still accepted.

**Class test:** every agent template's own `plan-update.json` example is fed to the validator, and every registry role that writes `plan-update.json` must be accepted. A new role added without a matching hook update now fails CI, not a live dispatch.

### 3. `## Linked artifacts` parsed for meaning (ISSUE-136, ISSUE-251)

The old parser took the first whitespace token verbatim:

| Line | 0.18 | 0.19 |
|---|---|---|
| `` - QA report: `docs/qa-reports/T-1.md` `` | backticks kept → "missing" → **blocked a clean PASS** | path checked |
| `- Deploy report: N/A (mobile build)` | looked for a file named `N/A` → **blocked** | declared absence (same as omitting the line) |
| `- **Deploy report:** docs/…` | label never matched → **checked nothing** | checked |
| `- QA reports: a.md + b.md` | plural never matched → **checked nothing** | every path checked |
| `- Deploy report: _pending_` | looked for a file named `_pending_` | blocked, with instructions |

A non-path value that is not a recognised N/A (`_pending_`, an unfilled `<placeholder>`) blocks with a message saying how to declare absence. It is never treated as a pass.

### 4. An explicit non-UI declaration outranks the track (ISSUE-049, ISSUE-181, ISSUE-286)

`ui-task-readiness-guard.isUITask` ran its `Track: fe` fallback **unconditionally**, so the sentinel checks just above it could never exempt an FE task. A non-visual FE task that declared `Design sub-status: n/a` and `Linked Surface: null` was still asked for four design artifacts owned by *other* roles. Its only ways out were to fabricate a design record or use the operator hatch. Separately, a sentinel followed by an HTML-comment rationale (`— <!-- behavioural fix -->`) was not recognised.

- If every design field that is present is a sentinel, and at least one is declared, the task is non-UI. The track fallback now applies only when **both** fields are absent. This is not self-exemption: task headers live in `docs/plan/**`, which is Orchestrator-only.
- `normalizeSurface` strips HTML comments, markdown emphasis and backticks, and any prose after a dash or semicolon.
- Includes the bold-metadata parsing fix from `3c82969`, now covered by tests.
- Against 4Run's 319 task files: 44 tasks flip from UI to non-UI, **every one explicitly declared non-UI**. None flip the other way.

### 5. Plan-consistency: no sibling wedges, no invisible tasks (ISSUE-236, ISSUE-282)

- **Touched rows only.** Every `master-plan.md` write used to validate every phase row. One stale digit in an unrelated phase made the file unwritable, and the error named the wrong phase. Now a row blocks only if this write adds or changes it. Drift in a row the write leaves untouched is reported as a **warning**.
- **Every table fragment is counted.** A `## Tasks` table broken by a blank line and a note used to be counted up to the first break only (4Run phase-54: 9 of 16). Fragments with the same columns are now counted; a table with a different shape (for example a coverage table keyed by task id) is not. Fragmentation is reported.
- **The filesystem is compared.** The id set of `tasks/T-*.md` must match the table. An **orphan** (a file with no row) or a **phantom** (a row with no file) blocks the phase.md write and is named. Phases with no task files at all (inline plans) are exempt.

### 6. TL worktree-free proposal tree is owned and removable (ISSUE-237)

§9 Step 4.6 keeps doc-writing roles, the TL included, in the main working directory, so the proposal tree's documented default location is `<root>/plan-proposal/`. The ownership map only knew the worktree location, so every TL write needed an escape hatch.

- `role-ownership`: a root-anchored `^plan-proposal/` row. Absolute paths under `CLAUDE_PROJECT_DIR` are normalised to project-relative paths first. A nested `docs/x/plan-proposal/` is **not** claimed.
- `orchestrator-bash-guard`: the root `plan-proposal/` tree, or anything inside it, is now a cleanup surface, so Step 7 can discard it. All existing refusals still apply: traversal, mixed targets, composition, symlinks.
- The TL template now states both locations.

### 7. docker-scope-guard (ISSUE-185, ISSUE-206)

- **Slug from the project, not the worktree.** Inside `.worktrees/<role>-<id>/` the slug came from the worktree name (`qa-exec-t-222b`), so the dispatch could not remove the containers it had created. Everything before `/.worktrees/` is now the root.
- **Per simple command.** Catastrophic patterns used `.*` across the whole string, so `docker rm p-web-1 && docker ps -a` was refused because of the *later* `-a`. The reverse was a real gap: only the first `docker` call was analysed, so `docker ps && docker rm other-project-db` was never checked. Commands are now split at unquoted separators, with `$(…)` substitutions kept inside their segment, and each segment is checked.
- **Redirections are not operands.** `docker rm p-web-1 2>&1` used to read `2>&1` as an out-of-scope container.

### 8. Escape-hatch instructions are reachable (class fix, ISSUE-206(1) / ISSUE-214 / ISSUE-219)

Twelve block messages across nine hooks told the agent to `export CLAUDE_X=1`. Hooks read the harness environment when they start, so an inline prefix or an `export` inside a Bash call never reaches them. The hatch looks inert, reads as a transient failure, and gets retried. Every message now says the variable must be set in the environment Claude Code is **launched** with. A class test fails if any hook reintroduces `export CLAUDE_*=1`.

### 9. Also in this release (from the same audit)

- **ISSUE-213**: `design-substatus-validator` reads the report's latest `Verdict` field instead of any occurrence of the word "qualified". A report recording `Verdict: unqualified` next to `Mapping-Status: qualified` passed.
- **ISSUE-192**: `srs-design-flow-validator` classifies `Design-Flow` (`A`, `A+B`, `A, B`, `A (Figma)`…) instead of comparing it to exactly `a`. Combined flows skipped every Flow-A check. An unrecognised value now **fails closed** and is named.

## Upgrade Notes

- Refresh **both** copies: the plugin (update the marketplace, then restart) **and** the project's vendored `.claude/hooks/`. Enforcement is the union of every registered copy, so a stale vendored copy keeps every old block.
- New shared lib `hooks/lib/kit-roles.cjs` must be vendored along with the hooks that require it (`lib/dispatch-promotion-state.cjs`, `plan-update-validator.cjs`).
- A project that keeps its own `.claude/hooks/lib/role-ownership.cjs` must drop any hand-written root `plan-proposal` row. The kit row replaces it (see §6).
- Stricter by design: bold or plural `Linked artifacts` labels and table fragments were previously unchecked. A task that declares a report file that does not exist will now be blocked at `in-test → done`.
