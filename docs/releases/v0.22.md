# Evo Talos SDLC Kit - Release Notes v0.22

**Release Date:** 2026-11-05

---

## Overview

v0.22 makes the kit Claude Code–only and fixes a false block in the UI readiness guard. The kit's enforcement relies on Claude Code hooks, sub-agents and project settings that have no Codex equivalent, so the Codex path ran without most of its gates.

---

## Breaking change — Codex support removed

Removed:

- `.codex-plugin/plugin.json` (Codex manifest).
- `skills/sdlc-init` and `skills/sdlc-loop` (Codex command shims; Claude Code uses `commands/sdlc-init.md` and `commands/sdlc-loop.md`).
- `skills/evo-devkit-contract` (a copy of `rules/CLAUDE.md` used only by the Codex loop shim).
- `agents/openai.yaml` metadata from 18 skills.

`scripts/sdlc-init.cjs`:

- Always writes `CLAUDE.md`, merges `.claude/settings.json`, copies `.claude/hooks`, and writes the lineage marker. Runtime detection is gone.
- Previously, when no agent environment or project marker was detected, the initializer **defaulted to Codex** and skipped hooks and settings. That fallback no longer exists.
- `--target claude` is accepted as a no-op for compatibility; `--target codex` and `--target both` now exit with an error.
- `CODEX_PROJECT_DIR` is no longer read; the project root is `--project`, `CLAUDE_PROJECT_DIR`, or cwd.

Release integrity: `check-release-version.cjs` and `test-vendored-parity.sh` now check two manifests (`.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`).

## Fix — `ui-task-readiness-guard` anchors the worktree on the plan-update.json path

When the hook fired with `cwd` set to the main project root while `plan-update.json` was written inside `.worktrees/<name>/`, the guard looked only in main. Artifacts committed in the worktree but not yet promoted exist only there, so a complete UI dispatch was blocked as missing every closure artifact.

- The worktree (and project root) now fall back to the `plan-update.json` path when the cwd does not identify one; relative `.worktrees/…` paths are resolved against cwd first.
- 4 new assertions; the 2 allow cases fail on 0.21.0. The block cases confirm an empty worktree still blocks and one task's worktree artifacts do not satisfy another task.

## Upgrade notes

- Projects initialized for Codex keep their `AGENTS.md` managed block; nothing removes it. Delete the block manually and run `/sdlc-init` in Claude Code.
- Projects running a **vendored** copy (`.claude/hooks/`) must re-run `/sdlc-init` to pick up the guard fix.
