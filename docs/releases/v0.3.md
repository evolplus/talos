# evo-talos Devkit v0.3 Release Notes

Release date: 2026-07-03  

## Summary

v0.3 hardens evo-talos in two places that were still too easy to bypass in v0.2: project initialization and design-governed delivery. The release makes `sdlc-init` aware of the active assistant runtime so it installs the right files by default, records trusted initialization receipts so later security audits can distinguish expected plugin-managed writes from suspicious ones, deepens brownfield discovery so reverse-engineering captures executable service boundaries and contract candidates, and strengthens local deployment guidance around env files and platform detection. On the UI path, v0.3 closes the remaining Flow A gaps by requiring Figma extraction and mapping evidence before SRS sign-off, requiring a real task handoff before `design-confirmed`, and refusing UI completion when the handoff, refs, and visual artifacts exist only nominally rather than with manifest-level evidence.

## Highlights

- `sdlc-init` now auto-detects Codex, Claude, or dual-target projects instead of assuming Codex by default.
- Initialization writes a short-lived receipt so the post-bash security audit can trust plugin-managed hook/settings changes made by `sdlc-init`.
- Brownfield archaeology now requires route and job traces, service-boundary maps, broker consumer logic, and API/message contract candidates before claiming extraction is sufficient.
- Local deployment guidance now requires env-file discovery and validation without exposing secrets, plus explicit host-architecture and Docker platform reporting.
- Flow A UI work now requires Figma extraction evidence, mapping evidence, and pinned node IDs before SRS sign-off can proceed.
- New runtime gate blocks `design-confirmed` until a task-scoped UI/UX handoff and qualified completeness report actually exist.
- FE and ready-for-deploy UI gates now require non-empty manifest, trace, and assertion rows rather than passing on artifact presence alone.
- Documentation and role ownership were updated so UI/UX Designer owns handoffs while FE Dev owns frozen `docs/uiux/refs/<task-id>.md` contracts.

## Added

### Initialization Receipts

`sdlc-init` now writes a receipt at `.claude/hooks/.state/sdlc-init-receipt.json` describing the files it installed and their hashes. The receipt is used by the post-bash security audit to suppress false positives for expected plugin-managed writes when initialization just ran.

### Brownfield Extraction Detail

The codebase archaeologist output now includes additional required sections for brownfield work:

- `Service Boundary & Entry Point Map`
- `Route / RPC / Job Trace Matrix`
- `Message Broker / Consumer Logic`
- `API / Message Spec Candidates`

This gives SA and BA reverse-engineering flows a stronger executable starting point instead of a shallow inventory.

### New Design Governance Hooks

Two new hooks were added:

- `hooks/srs-design-flow-validator.cjs`
- `hooks/design-substatus-validator.cjs`

Together they block premature advancement on Flow A UI work by enforcing pre-sign-off design evidence and post-sign-off task handoff readiness.

## Changed

### Project Initialization

`sdlc-init` now detects the active assistant runtime from environment signals first, then project markers if needed.

- Codex projects still receive `AGENTS.md` injection.
- Claude projects still receive `CLAUDE.md`, settings merge, and hook installation.
- `--target codex|claude|both` is now an explicit override instead of the primary selection mechanism.

This makes initialization safer for teams moving between Codex and Claude or maintaining dual-tool repositories.

### Post-Bash Security Audit

`hooks/post-bash-security-audit.cjs` now tracks sensitive-path changes with richer metadata and recognizes trusted `sdlc-init` writes when a fresh matching receipt exists. The audit still reports unexpected sensitive changes, but it stops treating plugin initialization itself as suspicious persistence activity.

### Local Deployment And DevOps Reporting

Deployment guidance now requires stronger environment and platform accounting:

- discover compose `env_file` usage and operator-owned `.env*` presence
- run compose env validation without printing secret values
- record `env_files`, `env_templates`, and `env_validation` in deploy reports
- detect host architecture and require explicit `--platform` handling
- surface emulation warnings when containers run under a non-native platform

These changes flow through `skills/local-deployment/SKILL.md`, the DevOps template, QA execution guidance, and user-facing docs.

### Brownfield Operational Rules

Brownfield onboarding now expects deeper evidence before marking archaeology sufficient for extraction.

- public surfaces must be traced end-to-end
- message flows must include producer, consumer, retry, and side-effect logic
- contract candidates must be named up front for REST, RPC, and async interfaces

The BA reverse-engineering and SA brownfield extraction skills were updated to consume this richer evidence.

### Flow A Design Lifecycle

Flow A now has explicit runtime enforcement across the whole design path.

- SRS sign-off states are blocked until Figma extraction artifacts exist, mapping status is acceptable, and Design References rows have pinned node IDs.
- Task files cannot move to `design-confirmed` until the UI/UX handoff and BA completeness report exist and are content-complete.
- UI/UX Designer guidance now requires token evidence from every Figma-backed dispatch, even when the file has no named Foundation or guideline page.
- Flow A post-sign-off work still needs `import`-mode task handoffs before FE may proceed.

### UI Artifact Gates

The existing FE and UI readiness guards are stricter in v0.3.

- Frozen refs must contain non-empty `Design Element Manifest` and `Implementation Trace Matrix` rows.
- UI/UX handoffs are now part of the required ready-for-deploy artifact set.
- Visual specs must contain non-empty `Design Element Assertions` rows.
- Readiness checks now fail when trace rows are still effectively placeholders.

## Fixed

- Reduced false positives from the post-bash security audit immediately after running `sdlc-init`.
- Closed the Flow A gap where an SRS could approach sign-off before extraction, mapping, and pinned-node evidence were complete.
- Closed the task-state gap where UI work could be marked `design-confirmed` before a usable task handoff existed.
- Reduced the chance of FE starting against nominally frozen but substantively empty design contracts.
- Reduced the chance of UI tasks reaching `ready-for-deploy` with incomplete handoff, refs, or visual-spec evidence.
- Reduced brownfield extraction ambiguity by requiring executable traces and contract candidates rather than high-level summaries alone.

## Compatibility And Upgrade Notes

- Projects initialized with v0.2 should re-run initialization to pick up target auto-detection, receipt writing, and updated hook/settings behavior:
  - Claude Code: `/sdlc-init`
  - Codex: `Run sdlc-init`
- Teams with mixed Codex and Claude usage should let v0.3 auto-detect the active environment, and only use `--target` when intentionally forcing a migration or dual-install path.
- Brownfield work started on v0.2 may need refreshed archaeology reports before SA/BA reverse-engineering so the new trace and contract-candidate sections are present.
- UI tasks already in progress may need refreshed handoffs, completeness reports, refs, or visual specs so they satisfy the stricter Flow A and ready-for-deploy gates.
- Flow A projects that previously relied on mapped coverage alone should expect an additional task-scoped handoff requirement before FE implementation begins.
