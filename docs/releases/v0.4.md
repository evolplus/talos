# Evo Talos SDLC Kit — Release Notes v0.4

**Release Date:** 2026-07-08

---

## Overview

v0.4 is a major refinement of the SDLC execution model, emphasizing safe finalization semantics, local-only agent worktrees, and specialized mobile framework support. The kit introduces new safety guards, six focused mobile skills, and clarifies the separation between sub-agent scratch commits and main-branch artifact promotion.

**Upgrade recommended for:** all projects running v0.3.x and earlier.å

---

## Major Features & Changes

### 1. Ready-to-Finalize Workflow (breaking semantic change)

**What changed:**
- Terminology shift: `"commit before signaling done"` → `"commit before signaling ready-to-finalize"`
- The signal now accurately reflects sub-agent state: when a sub-agent writes `plan-update.json`, it is **ready for finalization**, not yet done.
- Finalization is a distinct Orchestrator step that promotes artifacts, applies plan updates, and commits both together on main.

**Why:**
The old terminology conflated sub-agent completion with actual project completion. A sub-agent finishing its commits doesn't mean the artifacts are on main or the plan is committed. The new terminology makes this boundary explicit.

**Affected files:**
- All agent templates: `agents/_templates/*.md`
- All skill files: `skills/**/*.md`
- Core rules: `rules/CLAUDE.md`, `rules/hard-rules.md`, `rules/crash-recovery.md`, `rules/orchestrator-operating-rules.md`
- Commands: `commands/sdlc-loop.md`
- Hooks and messaging: `hooks/*.cjs`, `hooks/README.md`

**Migration impact:**
- Read `docs/plan/` task status: `ready-for-deploy`, `in-test`, `done`, `failed`, `interrupted` remain unchanged.
- Reword agent checklists and internal task notes from "done" to "ready-to-finalize" for consistency.
- No API or tool changes required for existing projects.

### 2. Local-Only Agent Worktree Safety

**What's new:**
- New hook: `local-worktree-git-guard.cjs` (PreToolUse)
- Detached local worktrees replace branch-backed agent branches:
  - Old: `git worktree add -b agent/<role>/<task-id> .worktrees/<role>-<task-id>/ HEAD`
  - New: `git worktree add --detach .worktrees/<role>-<task-id>/ HEAD`
- Blocked operations from `.worktrees/...` cwd:
  - `git push`, `git pull`, `git merge`, `git rebase`, `git cherry-pick`
  - Agent branch creation with `-b` or `--branch` flags
  - Any promotion of `agent/*` or `local-agent/*` branches

**Why:**
Sub-agent worktrees are scratch execution areas, not integration branches. Detached local commits are clean checkpoints for auditing; they are never meant to be merged, rebased, or pushed. This guard prevents accidental history rewriting and enforces the path-scoped artifact promotion model.

**Behavioral guarantees:**
- Sub-agents may commit locally to keep their worktree clean before `plan-update.json` (required by `task-completion-commit-check.cjs`).
- The Orchestrator validates exit criteria, copies/applies approved file paths to main, commits the promoted result on main, then discards the worktree.
- The worktree's local Git history is not an integration artifact — it is discarded with the worktree.

**Escape hatch:**
`export CLAUDE_ALLOW_LOCAL_WORKTREE_GIT=1` (operator-explicit, repair-only; not for routine dispatches).

**Updated files:**
- `hooks/local-worktree-git-guard.cjs` (new)
- `hooks/hooks.json` (added PreToolUse entry)
- `hooks/orchestrator-bash-guard.cjs` (updated Git patterns to defer push/pull/merge/rebase to local-worktree guard)
- `rules/worktree-isolation.md` (clarified detached-local semantics)
- `rules/hard-rules.md` (added agent worktree Git history constraint)
- `skills/git-commit/SKILL.md` (clarified no-push / no-merge from sub-agent worktrees)

### 3. Refined Finalization Flow

**What's changed:**
The Orchestrator's Step 7 (sub-agent return) now executes as a single finalization transaction:

1. Read `plan-update.json` from sub-agent worktree.
2. Validate exit criteria.
3. **Promote validated role-owned artifacts** by path-scoped ingestion (copy approved files from worktree to main).
4. **Apply `plan-update.json`** to produce next `docs/plan/` state.
5. **Stage promoted artifacts + plan updates together.**
6. **Create ONE finalization commit** containing both the artifact content and the master-plan transition.
7. Clean up worktree.
8. Delete dispatch journal entry.

**Why:**
Atomicity. The old model committed plan updates separately from artifact promotion, leaving a window where plan status didn't match on-disk artifacts. This window caused crash-recovery ambiguity. Now, plan status and promoted artifacts are always in sync: a single commit ensures this.

**Crash recovery impact:**
- If a session crashes mid-finalization, the worktree + `plan-update.json` remain, and reconciliation (§9 Step 0.6) re-runs the finalization transaction rather than discarding the work.
- If the finalization commit succeeds but cleanup doesn't, the journal and worktree are orphaned but harmless — reconciliation detects this and cleans up on the next session.

**Updated files:**
- `rules/orchestrator-operating-rules.md` (detailed §9 Step 7 finalization transaction)
- `rules/crash-recovery.md` (added ready-to-finalize check in §14.4)
- `rules/autonomous-loop.md` (clarified dispatch + finalize pattern)
- `commands/sdlc-loop.md` (updated dispatcher semantics)

### 4. Mobile Framework Specialization (6 New Skills)

**What's new:**
React Native and Flutter now route through focused companion skills, not monolithic "coding standard" playbooks.

**New skills:**
1. [`react-native-implementation`](./skills/react-native-implementation/SKILL.md) — screens, components, navigation, state, styling, accessibility, selectors, and ordinary unit/component tests.
2. [`react-native-performance`](./skills/react-native-performance/SKILL.md) — slow screens, large lists, image-heavy UI, animations, startup, memory, render-cost, and bridge overhead.
3. [`react-native-platform-integration`](./skills/react-native-platform-integration/SKILL.md) — native modules, permissions, deep links, push, secure storage, app config, iOS/Android files, and platform-specific behavior.
4. [`flutter-implementation`](./skills/flutter-implementation/SKILL.md) — widgets, pages, state, navigation, theming, accessibility, keys/semantics, and ordinary Dart/widget tests.
5. [`flutter-performance`](./skills/flutter-performance/SKILL.md) — rebuild churn, jank, large lists, image-heavy UI, animations, startup, memory, isolates, and layout/paint performance.
6. [`flutter-platform-integration`](./skills/flutter-platform-integration/SKILL.md) — platform channels, plugins, permissions, flavors, dart-define config, deep links, push, secure storage, native files, and platform-specific behavior.

**Loading rule:**
When `fe-framework-coding-standard` selects React Native or Flutter:
1. Always load the **implementation** skill.
2. Add the **performance** skill only when the task has performance-sensitive work or a performance acceptance criterion.
3. Add the **platform-integration** skill only when the task crosses the JS/native boundary or changes platform config.

**Why:**
Mobile development spans very different concerns — UI implementation, performance tuning, and native integration are rarely in the same task. Splitting them keeps context focused and prevents token waste on irrelevant guidance.

**Backwards compatibility:**
- `fe-framework-coding-standard` unchanged in its routing for ReactJS, Vue.js, Angular, Next.js.
- `references/react-native.md` and `references/flutter.md` become routing cards that redirect to the companion skills.
- No breaking change for existing projects; new projects benefit from focused guidance.

**Updated files:**
- `skills/fe-framework-coding-standard/SKILL.md` (updated description, added mobile skill map)
- `skills/fe-framework-coding-standard/references/react-native.md` (converted to routing card)

### 5. Security Audit & sdlc-init Improvements

**What's new:**
- `post-bash-security-audit.cjs` now detects `sdlc-init` commands and trusts sensitive-file changes when they match the receipt.
- `sdlc-init` writes `.claude/hooks/.state/sdlc-init-receipt.json` with SHA256 hashes of intentionally changed sensitive files.
- When re-running `sdlc-init` or a wrapper command, stale `ISSUE-SEC-*` findings are auto-resolved if every listed file still matches the trusted receipt.

**Why:**
sdlc-init intentionally changes kit files (hooks, rules, agents) in sensitive paths. The old audit would flag these changes every run, creating noise. The receipt + matching mechanism allows the audit to trust kit-controlled updates while still flagging unauthorized changes to the same paths.

**Behavioral flow:**
1. First `sdlc-init` run writes receipt with SHA256 hashes.
2. Post-audit may file `ISSUE-SEC-*` findings for new kit files.
3. On next audit (same or future session), if the operator runs `sdlc-init` again and every finding file matches the receipt hash, the audit auto-resolves the `ISSUE-SEC-*` entry with a note.
4. If any finding file is missing, modified, or mismatched, the issue stays open — operator action is required.

**Updated files:**
- `hooks/post-bash-security-audit.cjs` (added `commandLooksLikeSdlcInit()`, `projectRoot()` event-aware refinement, auto-resolution logic)
- `scripts/sdlc-init.cjs` (added `refreshInstallReceiptFiles()`, `resolveTrustedSdlcInitSecurityIssues()`, receipt tracking)
- `hooks/tests/test-security-audit.sh` (added sdlc-init audit test scenarios)

## Breaking Changes

### 1. Worktree Creation Model
**Old:**
```bash
git worktree add -b agent/<role>/<task-id> .worktrees/<role>-<task-id>/ HEAD
```

**New:**
```bash
git worktree add --detach .worktrees/<role>-<task-id>/ HEAD
```

**Impact:** Orchestrators must update worktree creation commands. The old branch-backed model is no longer supported; `local-worktree-git-guard.cjs` will refuse `-b` and `--branch` flags for `.worktrees/` creation.

### 2. Git Push/Merge from Sub-Agent Worktrees
**Old:** Allowed (merged by Orchestrator after validation).

**New:** Blocked by `local-worktree-git-guard.cjs` and `task-completion-commit-check.cjs`.

**Impact:** Sub-agents may commit locally, but must not attempt to push or merge. The Orchestrator handles promotion via path-scoped ingestion.

### 3. Artifact Promotion Timing
**Old:** Master-plan committed, then role-owned artifacts merged.

**New:** Role-owned artifacts promoted, then master-plan applied, all in one finalization commit.

**Impact:** Inspecting `git log` and `git diff` will show finalization commits that contain both plan state and artifact content. Scripts that parse commit messages or diff patterns should be updated if they assume plan and artifacts land separately.

## Deprecations

### 1. agent/<role>/<task-id> Branch Names
The `agent/` branch prefix is no longer created. Existing projects with orphan `agent/` branches from v0.3.x should delete them manually:
```bash
git branch -D agent/ba/T-001 agent/fe-dev/T-042 ...
```

### 2. Monolithic Mobile Framework References
The old `flutter.md` and `react-native.md` guides are now routing cards. Projects using v0.3.x skills should update agent dispatches to load the new focused companion skills for performance or platform integration work.

## Bug Fixes & Improvements

1. **Security audit noise reduction:** sdlc-init trusted receipt prevents repeated false-positive `ISSUE-SEC-*` findings.
2. **Crash recovery clarity:** Ready-to-finalize state is now explicitly checked before rolling back a dispatch.
3. **Bash guard precision:** Git operations now correctly deferred to local-worktree guard (not blocked by orchestrator guard).
4. **Orchestrator timing:** Finalization atomicity prevents plan/artifact sync gaps.

## Migration Guide

### For Existing Projects

1. **Update Orchestrator code:**
   - Change worktree creation from `git worktree add -b agent/...` to `git worktree add --detach ...`.
   - Update §9 Step 7 to run the finalization transaction (path-scoped ingestion + joint commit).

2. **Update documentation:**
   - Replace "commit before done" with "commit before ready-to-finalize" in task checklists and internal runbooks.
   - Update any scripts or CI jobs that parse finalization commits.

3. **Reconcile orphan branches (optional but recommended):**
   ```bash
   git branch -D $(git branch | grep '^.*agent/' | tr -d ' ')
   ```

4. **Optional: Load mobile companion skills for React Native/Flutter tasks going forward.**

### For New Projects

All new projects automatically use:
- Detached worktree creation.
- Ready-to-finalize finalization flow.
- Local-worktree Git safety guards.
- Focused mobile skills.

No additional setup required.

## Known Limitations

1. **Escape hatches remain rare-use only:** `CLAUDE_ALLOW_LOCAL_WORKTREE_GIT=1` is provided for operator-explicit repair, not routine use.
2. **Audit receipt matching is SHA256-based:** Whitespace or formatting changes in intentionally modified files will cause mismatches. Keep sdlc-init updates clean.
3. **Mobile skills are new:** Early feedback and documentation improvements welcome.
