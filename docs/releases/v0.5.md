# Evo Talos SDLC Kit - Release Notes v0.5

**Release Date:** 2026-07-27

---

## Overview

v0.5 strengthens agent-definition reliability and tightens UI design-governance enforcement. This release fixes generator and template metadata handling so generated agent files retain valid, parseable frontmatter (including non-empty `description` fields), and expands UI design gates from element-only checks to full frame-identity, composition, and asset-contract evidence.

Upgrade is recommended for teams using generated role agents and Figma-backed UI delivery.

---

## Major Features & Changes

### 1. Agent Definition Metadata Hardening

**What changed:**
- Agent template frontmatter descriptions are now emitted as YAML-safe quoted scalars.
- Generator instructions now explicitly require preserving a single parseable YAML frontmatter block in generated agent files.
- Generator flow now enforces frontmatter validation (`name`, non-empty `description`) and description sanitation when copying templates.
- Guidance now clarifies that duplicate or split frontmatter blocks are invalid for dispatch and must be treated as blocking errors.

**Why:**
Generated agents are dispatch targets. Missing or malformed frontmatter can silently break role routing and cause orchestrator-level stalls.

**Impact:**
- Lower risk of silent dispatch failures from malformed metadata.
- More deterministic generation behavior across template and specialized agent files.

### 2. UI Design Contract Enforcement Expansion

**What changed:**
UI design gates now require more than manifest presence. Enforcement now includes:
- `Reference Render` evidence with node/checksum details.
- `Visual Composition Contract` evidence (viewport/layout/layer/constraints).
- `Asset Export Manifest` evidence with AST rows and blocked-asset rejection.
- Traceability sections for assets and composition, in addition to element-level traces.

**Why:**
Element presence alone was not sufficient to prevent wrong-frame implementation, missing visual assets, or layout drift.

**Impact:**
- Higher confidence that FE implementation matches the approved frame identity, composition, and assets.
- Earlier blocking of incomplete handoffs/contracts before source writes or readiness transitions.

### 3. Expanded Hook Validation and Test Coverage

**What changed:**
- `design-substatus-validator` now enforces non-empty reference/composition/asset evidence and rejects blocked asset rows.
- `fe-dev-design-contract-guard` now checks for full visual-contract sections and AST/CMP evidence.
- `ui-task-readiness-guard` now validates composition/asset assertions in addition to design-element assertions.
- Hook tests were extended with new pass/fail fixtures covering incomplete visual contracts and blocked assets.

**Why:**
Runtime enforcement needed to match updated policy so design-confirmed and ready-for-deploy cannot advance on nominal artifacts.

**Impact:**
- Better alignment between documented process and executable gates.
- Reduced chance of regressions slipping through due to incomplete UI artifacts.

### 4. SDLC Rules and Skill Guidance Alignment

**What changed:**
Multiple role skills and rules were updated to align with the stricter design symmetry model:
- Handoffs now require frame identity proof, composition contract, and asset manifests.
- BA completeness and post-implementation checks now include composition/asset completeness criteria.
- FE standards now require implementing contracted composition and required exported assets, not approximate substitutes.
- QA authoring and execution guidance now includes composition and asset assertion coverage.

**Why:**
Cross-role consistency is required so every phase validates the same contract surfaces and failure modes.

## Breaking / Behavior Changes

### 1. Stricter UI Gate Requirements
Tasks that previously passed with manifest-only artifacts may now be blocked unless reference render, composition, and asset sections are present and complete.

### 2. Blocked Asset Rows Are Hard Failures
Any required asset row marked blocked in handoff or refs evidence now prevents progression until resolved.

### 3. Generator Metadata Expectations Tightened
Template or generated agent files missing valid frontmatter metadata (`name`, non-empty `description`) are now explicit blockers rather than tolerated inconsistencies.

---

## Compatibility & Upgrade Notes

- Re-run generation flows so specialized agent files are produced from updated metadata rules.
- Refresh in-flight UI task artifacts (`handoffs`, `refs`, `visual-specs`) to include the new required evidence sections.
- Expect stricter enforcement at `design-confirmed` and `ready-for-deploy` transitions for UI-bearing tasks.

---

## Validation

Validation for this release includes expanded in-tree hook tests in `hooks/tests/test-hooks.sh`, with new scenarios for:
- incomplete visual handoff evidence,
- blocked asset entries,
- refs contracts missing composition/asset trace sections,
- readiness checks requiring composition and asset assertions.

---

## Notes

This release is focused on reliability and enforcement depth rather than introducing new roles or runtime commands.
